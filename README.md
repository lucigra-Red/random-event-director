# 随机事件导演 V0.1.1

一个可独立安装的 **标准 SillyTavern 第三方 Extension**。不使用 Luker Extension API，不修改酒馆核心，不要求安装酒馆助手。仅实现：副 AI 生成候选事件 → 聊天事件池 → 本地随机 → pending → 本轮隐藏注入 → Assistant 成功回复 → 消费。

## 安装与开启

1. 解压 `random-event-director-v0.1.1.zip`。从 V0.1.0 升级时覆盖同名扩展文件夹后刷新页面；原聊天 metadata 保留，缺少预设的旧聊天自动使用默认预设。
2. 将完整的 `random-event-director` 文件夹放到 SillyTavern 的用户扩展目录，例如 `SillyTavern/data/default-user/extensions/random-event-director/`。也支持标准共享第三方扩展目录 `SillyTavern/public/scripts/extensions/third-party/random-event-director/`。二选一，不要安装两份。
3. 确认 `manifest.json` 位于这个文件夹的第一层，旁边有 `index.js`、`engine.js`、`api.js`、`ui.js`、`presets.js`、`preset-ui.js` 和 `style.css`。
4. 刷新酒馆页面，在“扩展设置”展开 **随机事件导演**。
5. 打开角色聊天、连接正常使用的酒馆 API，再勾选 **开启本聊天的随机事件导演**。默认关闭；每个聊天分别开启。
6. 开启时在后台生成第一池事件；也可点击 **生成 / 重新生成事件池**。生成期间可继续正常聊天。

也可以在酒馆“扩展 → 安装扩展”中填写仓库地址：`https://github.com/lucigra-Red/random-event-director`。通过仓库安装后刷新页面，在扩展设置中开启。本地安装与仓库安装二选一，不要安装两份。用户不需要 npm、构建工具、额外服务器或数据库。

## 默认配置

| 设置 | 默认值 |
|---|---:|
| 本轮触发概率 | 25% |
| 目标候选数量 | 6 |
| 自动补充阈值 | 2 |
| 旧池过期 | 7 个 Assistant 消息回合 |
| 近期剧情 | 最近 16 条非系统消息 |
| 近期正文总字符上限 | 24,000；每条最多 6,000 |
| 副 AI 超时 | 45 秒 |

前六项可在面板调整。数量 1～20，概率 0～100%；设置目标数量小于阈值时，有效阈值自动限制到“目标数量 − 1”。概率 0% 仍允许主动使用“立即掷骰”。

## 副 AI 调用与上下文

默认复用当前酒馆连接与当前模型，**另外发起独立的事件规划请求**，不会写一条副 AI 聊天消息。取消“使用当前酒馆 API 的当前模型”，可以从已有模型选项中选择或填写同一个 API 提供方下的其他模型 ID。它不切换主模型；不能用这里的模型 ID 代替其他提供方的账号配置。

调用酒馆公开的 `ChatCompletionService` / `TextCompletionService`：先用 `presetToGeneratePayload` 构造当前配置的独立副请求，再用 `sendRequest` 发出。当前连接、服务端密钥、代理及模型参数由酒馆处理；插件不收集、不保存 API Key，不自建 Provider/代理客户端。副请求使用非流式、单候选、最大输出 2,200 tokens，传入独立 AbortSignal。未选择酒馆参数预设时温度为 0.8；选择后由该预设提供温度等酒馆服务支持的生成参数。

V0.1 支持酒馆 **Chat Completion**（酒馆内部 `mainApi: openai`，包括通过该界面连接的兼容提供方）和 **Text Completion**（`textgenerationwebui`）。其他主 API、缺少上述服务的旧版本会显示错误并跳过副系统，普通聊天照常。Text Completion 使用简明角色分隔文本；不额外实现各模型的聊天模板。

副 AI 读取近期非系统消息、当前角色的描述/人格/场景，以及面板中可选的补充世界观。背景最多 12,000 字符。**不扫描全部世界书，也不复用整个主聊天预设**；世界书中的重要设定需要在补充世界观里写明。不会向副 AI 提供本次已经抽中的隐藏提示词。

事件请求只要求事件起因，禁止代替玩家行动、修改人格、写出结果或由 AI 选择事件。解析接受 JSON 和 JSON 代码围栏；验证标题、正文与长度，去重、规范权重，并生成本地 ID。有效结果不足 6 个时接受较小池，并在正常补充机会再补；不会无限重试凑数。

## 导演预设管理（V0.1.1）

在扩展面板展开 **导演预设管理**。默认预设始终保留；选择预设只载入编辑器，点击“应用到本聊天”才生效。

- **副 AI 事件生成提示词**：编辑事件风格、强度、世界动态偏好，必须含 `{{count}}`。
- **主 AI 隐藏注入模板**：编辑事件演出方式，必须含 `{{event}}`；还可用 `{{title}}`、`{{type}}`。
- 两处都可使用 `{{char}}`、`{{user}}`，分别替换为酒馆当前角色和玩家名称。模板只做一次字面替换，不执行代码或递归替换事件正文。
- **副 AI 酒馆生成参数预设**：从当前 API 的原生预设列表选择，单次请求读取该预设的参数。它不切换主聊天配置；不自动导入原生预设的完整 prompts/prompt_order 链。完整导演提示词由上述两个编辑框控制。
- **保存预设**：保存到跨聊天的导演预设库并应用到当前聊天；默认预设被另存为自定义项。**另存为**创建副本，同名自动编号。**恢复默认**不删除自定义库。
- **导入 / 导出 JSON**：支持选中项或全部自定义项的导出、JSON 文本导入、JSON 文件导入与文件下载。导入只新增，同名编号，验证全部内容后才写入；不会覆盖既有项或自动改变当前聊天。格式是导演自己的 `random-event-director-presets`，不是原生酒馆预设 JSON。最多 30 个自定义项。

预设库通过 `extensionSettings.random_event_director_presets_v1` 和 `saveSettingsDebounced()` 保存。每个聊天在既有 metadata 内保存所选预设的完整快照，因此改动/删除全局库不会偷偷改变其他聊天的规则。删掉库中的预设后，当前聊天快照仍可使用，也可重新保存到库。

切换提示词或参数预设时取消旧副请求、清空旧可用池；开启状态下后台生成新池。**已准备的 pending 和本轮的隐藏注入文本保持原样**，包括手动 pending、失败重试、regenerate 与 swipe。新回合才使用新模板。主模型生成期间不允许应用预设。

自定义提示词仍保留固定 JSON 输出协议和起因/玩家自主权约束，自定义隐藏模板仍追加自然演出与隐藏系统约束。不能通过删除模板中的约束来改变本地随机或成功后消费的程序逻辑。

包内 `examples/旅馆日常.json` 提供一个可直接导入的轻松日常示例。

## 事件池、随机与注入

- 事件池、开关、概率、pending、最近触发、批次回合及本轮决定保存在 `chatMetadata.random_event_director_v1`，通过酒馆 `saveMetadata()` 保存。用户消息 `extra` 保存稳定锚点 ID；成功 Assistant 消息和当前 swipe 信息保存本轮关联。正文不被修改。
- 两次独立的本地判定：`crypto.getRandomValues` 的拒绝采样产生 0～9,999，和百分比比较；命中后再按规范化的整数权重抽事件。未提供权重默认 10，即等概率。AI 从不决定抽取结果。不使用 `Math.random` 兜底；没有 crypto 时安全跳过。HTTP 局域网页面缺少 `randomUUID` 时用同一个 crypto API 生成本地 UUID。
- 抽中即从可用列表移到 pending；本轮决定保存事件快照。**连“未触发”也会保存**，修改概率后重生成仍不会重新掷骰。
- 原生 manifest `generate_interceptor` 只做同步本地操作；用 `setExtensionPrompt` 在聊天内深度 0、system role 注入本轮情境。提示词要求自然融入、保留人格、不给玩家预设行动、禁止提及骰子/插件/隐藏系统。不会插入或伪装用户消息。
- 在回复、停止、结束、切换聊天、关闭或页面卸载时清除注入。quiet、impersonate、首次问候和预览不参与掷骰。关闭后不调用副 AI、不随机、不注入剧情内容。
- 库存 ≤ 阈值时在生成结束后后台补充；旧批次超过配置回合数后丢弃。补充保留原批次年龄，重新生成完整池才重置年龄。空池当轮直接跳过，不等待副 AI 返回。自动请求间隔至少 30 秒，并且至少经过 2 个 Assistant 回合；手动重新生成可绕过间隔。错误也遵守间隔，避免请求失败后每轮反复调用。

## pending、regenerate、swipe 与聊天隔离

pending 绑定对应用户消息锚点；已有回复的 regenerate / 新 swipe / continue 通过 Assistant `extra` 找回原本的事件快照。停止或失败时保留 pending，成功后标记 consumed 并清除 pending。已经 consumed 的事件仍保留本轮快照以便重生成复用，但不会再次消费。

**`GENERATION_ENDED` 仅清理，不表示成功。** 消费需要匹配当前聊天和本轮、非空 Assistant 正文、完成时间、有效生成类型，并排除已中止信号、流式 `isStopped` / abort。酒馆流式错误也可能发 `MESSAGE_RECEIVED`，所以单凭这个通知也不足以消费。

“立即掷骰”绕过发生概率，抽取一个 pending，**不调用主 AI、不增加聊天消息**。没有可用事件时可以先生成池；重复点击保留已准备事件。手动 pending 只交给下一次正常新回合，不改变已完成回复的重生成。

聊天身份结合角色 avatar/群组 ID 与酒馆 chat ID；切换时清除运行中注入，取消副请求，拒收旧聊天的迟到结果。刷新从聊天 metadata 与消息 extra 恢复；复制到新分支或改名后聊天身份变化，保守清空池和旧本轮状态、保留设置。编辑用户消息会重新建立锚点；删除/编辑/切换已存在 swipe 会清空可用池，避免旧场景候选沿用。正常 regenerate 导致的 Assistant 删除保留原决策。

群聊将一个用户回合的事件交给第一个成功回复的成员，后续成员不重复收到它。只有实际收到事件的那个回复可重放它。未安装/未启用期间生成的历史回复没有决策快照，重生成时不会临时补一次随机。

## 文件与维护

| 文件 | 用途 |
|---|---|
| `manifest.json` | 标准扩展入口与生成拦截器声明 |
| `index.js` | 公共 API 接线、错误保护、监听注销 |
| `engine.js` | 聊天状态、事件池、随机、回合绑定和生命周期 |
| `api.js` | 复用酒馆的独立请求服务 |
| `ui.js` / `style.css` | 扩展设置面板与安全文本展示 |
| `presets.js` / `preset-ui.js` | 默认模板、预设库、导入导出及编辑管理界面 |
| `examples/旅馆日常.json` | 可导入的导演预设示例 |
| `RESEARCH.md` | 两个参考仓库与方案取舍 |
| `TESTING.md` / `tests/` | 自动测试、浏览器验证与实机检查说明 |

重复加载会先注销旧监听；页面卸载清除注入、取消副请求。普通使用时，“查看事件池”默认收起；用户主动展开才渲染候选内容，AI 输出用 `textContent` 展示，不作为 HTML 执行。

## 已知限制

此目录原先只有角色卡、世界书和图片，没有正在开发的酒馆源码或已连接的模型测试环境。已完成源码接口核实、自动化测试和模拟浏览器验证；**没有宣称在你的实际酒馆账号上跑过真实模型**。模型是否遵守起因约束、自然演出且不暴露提示词，需要按 `TESTING.md` 的实机步骤验证；提示词不能绝对保证任何模型的输出行为。

状态持久化依赖酒馆自身聊天保存正常工作。无法把“模型成功输出文本”证明为“剧情中确实演出了该事件”；本版以成功回复为消费依据。世界观来源、Text Completion 模板和群聊逐成员流程保持简单，不实现世界书全量激活、完整 CoC、长期事件树或多副 AI。
